# InvenTree Card - Architecture Overview
*Last Updated: October 5, 2025*

## 🎯 Project Purpose

**InvenTree Card** is a full-featured Home Assistant custom Lovelace card that bridges **InvenTree** (inventory management) with **Home Assistant** (home automation). It's a CRUD-capable, visually dynamic interface that:

- **Displays** inventory data from InvenTree
- **Reacts** to sensor data, stock levels, and parameters with visual effects & animations
- **Triggers** Home Assistant services and InvenTree API updates
- **Allows** conditional logic to control visibility, styling, and behavior
- **Supports** custom layouts with drag-and-drop grid system

Think of it as: **"A living dashboard that makes your inventory responsive to your smart home"**

## 🏗️ Architecture Layers

The system is built in **3 distinct layers**:

```
┌─────────────────────────────────────────────┐
│  Layer 1: Lit Element Wrapper               │  ← Web Component (inventree-card.ts)
│  - Lifecycle management                     │
│  - Home Assistant integration               │
│  - Configuration handling                   │
└─────────────────────────────────────────────┘
              ↓ Mounts & passes props
┌─────────────────────────────────────────────┐
│  Layer 2: React Application                 │  ← React + Redux (react-app.tsx)
│  - Redux Provider                           │
│  - Redux Persist                            │
│  - State management                         │
└─────────────────────────────────────────────┘
              ↓ Renders
┌─────────────────────────────────────────────┐
│  Layer 3: Component Tree                    │  ← Views & Logic
│  - Layout renderers (Table, Grid, etc.)    │
│  - Conditional logic evaluation             │
│  - Action execution                         │
│  - Visual effects application               │
└─────────────────────────────────────────────┘
```

### Why This Architecture?

1. **Lit Element Wrapper**: Home Assistant requires custom elements. Lit handles the web component lifecycle.
2. **React Core**: Better DX for complex UIs, rich ecosystem (Framer Motion, React Grid Layout).
3. **Redux State**: Centralized state for multi-source data coordination (InvenTree API + HA entities).

## 🔄 Data Flow

### Initialization Flow
```
User adds card to dashboard
        ↓
inventree-card.ts: setConfig() called by Lovelace
        ↓
Generate stable cardInstanceId
        ↓
Dispatch initializeCardThunk()
        ↓
- Store config in Redux
- Register card instance
- Fetch initial InvenTree data
- Subscribe to HA entity updates
        ↓
Mount React app with props (hass, config, cardInstanceId)
        ↓
InventreeCard.tsx renders layout
        ↓
Layout fetches parts, evaluates conditions, applies effects
```

### Runtime Update Flow
```
HA Entity State Changes
        ↓
Lovelace calls updated() on Lit element
        ↓
Pass new hass object to React app
        ↓
useEffect in InventreeCard.tsx detects hass change
        ↓
Dispatch fetchHaEntityStatesThunk()
        ↓
Update genericHaStates slice
        ↓
Dispatch evaluateAndApplyEffectsThunk()
        ↓
ConditionalEffectsEngine evaluates rules
        ↓
Update visualEffects slice
        ↓
Components re-render with new styles/animations
```

### Action Execution Flow
```
User clicks button in grid cell
        ↓
CellRenderer calls ActionEngine.executeAction()
        ↓
ActionEngine resolves action definition from Redux
        ↓
Process templates (e.g., %%part.pk%%)
        ↓
Execute operation:
  - call_ha_service → hass.callService()
  - update_inventree_parameter → inventreeApi.endpoints.updatePartParameter
  - dispatch_redux_action → store.dispatch()
  - trigger_conditional_logic → evaluateAndApplyEffectsThunk()
        ↓
If postEvaluationLogicIds defined, re-evaluate conditions
        ↓
Visual effects update, UI reflects changes
```

## 🧩 Key Subsystems

### 1. **State Management (Redux)**
**Location**: `src/store/`

**Slices**:
- `configSlice`: Card configuration, layout cells
- `partsSlice`: InvenTree parts data
- `parametersSlice`: InvenTree part parameters
- `genericHaStateSlice`: Home Assistant entity states
- `visualEffectsSlice`: Computed visual effects (colors, animations, visibility)
- `actionsSlice`: Action definitions (buttons, triggers)
- `componentSlice`: Card instance tracking
- `websocketSlice`: WebSocket connection status
- `uiSlice`: UI state (selected part, active view, debug panel)
- `loggingSlice`: Logging configuration
- `metricsSlice`: Performance metrics

**APIs (RTK Query)**:
- `inventreeApi`: InvenTree REST API endpoints
- `loggingApi`: (appears unused/deprecated?)

**Thunks**:
- `initializeCardThunk`: Card setup on mount
- `destroyCardThunk`: Cleanup on unmount
- `evaluateAndApplyEffectsThunk`: Conditional logic evaluation
- `fetchHaEntityStatesThunk`: Sync HA entities to Redux

---

### 2. **Conditional Logic Engine**
**Location**: `src/core/ConditionalEffectsEngine.ts`

**Purpose**: Evaluates rules and applies visual effects based on data.

**Key Concepts**:
- **ConditionalLogicItem**: A named container for logic pairs
- **LogicPair**: `{ conditionRules, effects }`
  - `conditionRules`: RuleGroup (from react-querybuilder)
  - `effects`: Array of effect definitions

**Rule Types**:
- **Generic Rules**: Reference HA entities (e.g., `sensor.temperature > 25`)
- **Part-Specific Rules**: Reference part data (e.g., `part_stock < 10`, `inv_param_Weight > 50`)

**Effect Types**:
- `set_style`: Apply CSS properties (background, color, border)
- `animate_style`: Apply Framer Motion animations
- `set_visibility`: Show/hide parts or cells
- `set_thumbnail_style`: Apply filters/opacity to images
- `set_layout`: Dynamically adjust grid layout

**Evaluation Strategy**:
1. Clear all previous effects
2. Evaluate generic rules once (apply to all parts unless targetPartPks specified)
3. Evaluate part-specific rules for each part
4. Merge effects (cell-specific > part-specific)
5. Dispatch to `visualEffectsSlice`

---

### 3. **Action Engine**
**Location**: `src/services/ActionEngine.ts`

**Purpose**: Execute user-triggered actions (button clicks, etc.)

**Action Operations**:
1. **call_ha_service**: Call Home Assistant services (lights, switches, etc.)
2. **update_inventree_parameter**: Update InvenTree part parameters via API
3. **dispatch_redux_action**: Trigger Redux actions (e.g., navigate, select part)
4. **trigger_conditional_logic**: Re-evaluate conditional logic
5. **set_card_state**: (Not fully implemented)

**Features**:
- Template processing: `%%context.part.pk%%`, `%%context.part.name%%`
- Confirmation dialogs
- Infinite loop prevention (tracks executing actions)
- Expression evaluation for `isEnabledExpressionId` (button enable/disable)

---

### 4. **Layout System**
**Location**: `src/components/layouts/`

**Layouts**:
- **TableLayout**: Grid-based layout using `react-grid-layout`
- **PartsLayout**: (Legacy? Need to check implementation)
- **DetailLayout, GridLayout, ListLayout, VariantLayout**: (Appear unused in current code)

**Cell System**:
- **CellDefinition**: `{ id, partPk, content, x, y, w, h, buttons?, isHidden? }`
- **CellRenderer**: Renders cell content (thumbnail, buttons, description, or dynamic field)
- Content types:
  - `thumbnail`: Display part image
  - `buttons`: Render action buttons
  - `description`: Show part description
  - Dynamic: Any dot-path to part data (e.g., `in_stock`, `IPN`)

**Visual Effects Application**:
- Part-wide effects: Apply to entire part row
- Cell-specific effects: Apply to individual cells (higher priority)
- Merged in CellRenderer: `{ ...partEffects, ...cellEffects }`

---

### 5. **Data Sources**
**Location**: `src/store/apis/inventreeApi.ts` + HA integration

**InvenTree API**:
- Endpoints: `getPart`, `getPartParameters`, `updatePartParameter`, `getPartStock`, etc.
- Base query: `inventreeBaseQuery.ts` (handles auth, base URL)
- Caching: RTK Query automatic caching

**Home Assistant**:
- Direct access: `hass` object passed as props
- Redux sync: `fetchHaEntityStatesThunk` updates `genericHaStateSlice`
- WebSocket: Optional real-time updates via `websocketMiddleware.ts`

**Polling Fallback**:
- If WebSocket disconnected, InventreeCard.tsx sets up interval to re-evaluate effects
- Default: 30 seconds (configurable via `config.performance.rendering.idleRenderInterval`)

## 🔗 Integration Points

### Home Assistant Integration
1. **Custom Element Registration**: `customElements.define('custom:inventree-card', InventreeCard)`
2. **HACS Registration**: `window.customCards.push(...)`
3. **Lovelace Lifecycle Hooks**:
   - `setConfig()`: Receive configuration
   - `set hass()`: Receive HA state updates
   - `connectedCallback()` / `disconnectedCallback()`: DOM lifecycle

### InvenTree Integration
- REST API calls via RTK Query
- Authentication: Stored in config (`inventree_host`, `inventree_token`)
- Data sync: Fetched on mount, cached in Redux

### Framer Motion Integration
- Animations defined in `visualEffects.animation`
- Applied in CellRenderer via `motion.div`
- Presets: Defined in `src/core/constants.ts` (e.g., `ANIMATION_PRESETS.pulse`)

### React Grid Layout Integration
- Layout config stored in `config.layout.cells`
- Each cell: `{ id, x, y, w, h, ... }`
- ResponsiveReactGridLayout renders grid
- Dragging/resizing disabled in view mode, enabled in editor

## 📊 Configuration Structure

Example config YAML:
```yaml
type: custom:inventree-card
name: My Inventory
inventree_host: http://inventree.local:8000
inventree_token: YOUR_TOKEN
data_sources:
  part_pks: [123, 456, 789]  # Parts to fetch
  ha_entities:               # HA entities to monitor
    - sensor.temperature
    - binary_sensor.door
layout:
  type: table
  rowHeight: 60
  cells:                     # Grid cells definition
    - id: cell-1
      partPk: 123
      content: thumbnail
      x: 0
      y: 0
      w: 4
      h: 2
    - id: cell-2
      partPk: 123
      content: buttons
      buttons:
        - actionId: action-1
          icon: mdi:plus
      x: 4
      y: 0
      w: 2
      h: 2
actions:
  - id: action-1
    name: Add Stock
    operation:
      type: update_inventree_parameter
      parameterName: Stock
      valueTemplate: '%%context.part.stock%% + 1'
conditionalLogic:
  - id: logic-1
    name: Low Stock Alert
    logicPairs:
      - conditionRules:
          combinator: and
          rules:
            - field: part_stock
              operator: <
              value: 10
        effects:
          - type: set_style
            styleTarget: Row
            styleProperty: highlight
            styleValue: '#FF0000'
          - type: animate_style
            preset: pulse
```
